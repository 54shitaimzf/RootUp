# 0.8.4 边界与职责审查报告

> 审查时间：0.8.4 里程碑收尾；依据：`docs/ARCHITECTURE.md` 依赖规则与 0.8.4 执行计划 M11。

## 自动化门禁（全部通过）

- `npm run check:arch`：288 处前端相对导入，`pages → features → components/hooks → lib` 单向依赖，无违规。
- `npm run check:arch:rust`：53 个 Rust 文件分层规则通过：
  - `core` 生产代码不引用 `tauri` / `crate::infra` / `crate::commands` / `crate::app`；
  - `commands` 不引用 `crate::app`；
  - `infra` 不引用 `crate::commands` / `crate::app`。
- `cargo clippy --all-targets -- -D warnings`、`cargo fmt --check`、Rust 298 项测试、前端 402 项测试全绿。

## 职责边界核对

| 检查项 | 结论 | 说明 |
| --- | --- | --- |
| core 纯业务 | 通过 | 新增 `FileEnumerator` / `ScanDiffStore` 契约、目录校验、状态机均位于 core，无 Tauri/存储依赖。 |
| commands 保持薄适配 | 通过 | 只做参数校验与编排（如 `query_files` 白名单、`app_ready` 委托），业务实现留在 core/infra。 |
| infra 平台适配单一职责 | 通过 | `WalkDirEnumerator`=遍历、`SqliteIndexStore`=存储与差集、`ScanService`=扫描编排、`ArchiveService`=自动归档队列、`FileLogger`=日志落盘、`managed_state`=托管状态刷新、`startup`=启动门控。 |
| 组合根只做装配 | 通过 | `app.rs` 仅注册插件/命令/服务与生命周期；托管刷新与延迟启动均委托 infra。 |
| 数据流单向 | 通过 | 设置变更 → `managed_state::refresh` → 服务；服务事件 → 前端；托盘反向变更补发 `settings-changed`。 |
| 前端分层 | 通过 | `lib/tauri.ts` 为唯一 invoke 边界；排序/校验纯函数在 lib；FilePage 只做状态装配。 |
| 无跨层回指 | 通过 | 上一轮 `app.rs`/`QuitFlag` 依赖已清除，本轮新增命令/服务均未引入反向依赖。 |

## 遗留与说明

- 性能基线存在若干 >15% p50 变化（系统启动/空闲内存；引擎查询类经最终重测回到 0.8.3 同量级），已记录到 `benchmarks/` 0.8.4 官方基线；统一列入 0.8.5 性能迭代复测与优化，不作为本次边界问题。
- jwalk 未引入（决策记录见 `benchmarks/jwalk-evaluation.md`），`FileEnumerator` 插槽已就绪。
- 托盘初始化延迟到前端就绪（含 10 秒回退），窗口销毁/托盘重建生命周期契约未破坏。

## 结论

0.8.4 代码分层与职责边界无未决违规，可进入 UI 审查与发布收尾。
