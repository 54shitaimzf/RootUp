## 阶段一：设置状态 bug 类根治（已落地）

发现（审计编号沿用审计记录）：
- S1/S2 设置页加/删监控目录用渲染闭包旧快照拼整表回写 `watched_dirs`；
- S3 `useSettings` 收 `settings-changed` 直接覆盖内存态，可清掉 500ms 防抖内未落盘补丁；
  刷新失败被静默吞掉；
- M1 五处 `replace({...settings, ...draft})` 整对象写，与托盘写入者存在静默回滚窗口；
- 后端 `set_settings` 文档级覆盖、写 settings.json 的路径有 5+ 条（含归档项目隐式重写 +
  手工 settings_backup 回滚）、互不感知且不发事件。

修复：
- `core/settings.rs` 新增 `SettingsPatch`（`watched_dirs` / `project_dirs` 有意移出补丁，
  强制走专用命令）+ `apply_patch` / `dirty_keys`；
- 命令 `set_settings` → `update_settings(patch)`；新增 `infra/settings_io.rs` 写入单入口
  （互斥 Mutex：load → mutate → validate → save → refresh → emit），
  命令 / 托盘 / 归档 journal 全部写路径接入；启动自愈保留直写（装配期不可 refresh）并注明；
- 所有成功写设置统一广播 `settings-changed`（载荷 `{ keys: [字段名] }`）；
- 归档 / 撤销项目改为**目录移动成功后**重读最新设置再做 project_dirs 重映射，缩小竞态窗口；
- `useSettings`：`update`/`commit` 只发变更字段补丁（commit 吸收挂起补丁防丢字段）、
  事件先冲刷挂起补丁再拉真源、刷新失败重试一次 + 日志、新增 `mergeLocal`（纯本地回显，
  永不持久化）与 `syncFromBackend`；SettingsPage 六处整对象写改增量。

## 阶段二：双端漂移真相契约化（已落地）

- **`cat:` 语义修复**（历史 bug：chips/自动补全把类别 key 塞进 `type:`，
  后端按精确扩展名匹配导致点「文档」chip 永远 0 结果）：
  后端 `cat:`/`category:`（合法 key 按标签匹配、未知回落文本）、前端 chips/补全迁移、
  `type:` 语义钉死并文档化；
- 契约 fixture（双端分别断言各自职责，Rust 为权威解释器）：
  - `fixtures/query-grammar-cases.json` 搜索语法；
  - `fixtures/archive-dest-cases.json` 归档目标路径派生（**抓到并修复真实边界 bug**：
    盘根作归档根时后端拼出 `D://category/...` 双斜杠）；
  - `fixtures/classify-effective-cases.json` 生效分类映射；
  - `fixtures/study-week-cases.json` 学业周次解析与相交；
  - `fixtures/app-contracts.json` 扩容：IDE 白名单 / 项目类型清单 / 标签 key 规则，
    `FILE_STATES` 补齐后端单向门禁；
- `ArchiveOutcome.results` 透出真实 source→dest 映射（含 `unique_dest` 冲突改名），
  展示与撤销核对以后端数据为准；
- 删除前端校验镜像 `pathValidation.ts`（规则唯一源归后端 `validate_dir_path`，
  前端只保留 `cleanPathInput` 清洗与错误透传）。

## 阶段四：错误契约（→ ROADMAP v0.8.8「错误码注册表」扩充）

- 现状：后端约 136 处硬编码中文 `Err(String)`，前端约 40 处 `String(err)` 裸展示
