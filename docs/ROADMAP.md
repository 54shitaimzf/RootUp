# 开发路线图（ROADMAP）

> 版本 = 一个可发布闭环。0.8.3 为存量补丁；0.8.x 为迭代线（Radix · 扎根，架构小步 + 功能，允许 schema 小步迁移）；0.9.x 为平台线（Hedera · 展藤，AI + 生态）；v1.0 为稳定发布里程碑（Mentha · 常青薄荷）。每个版本均带验收，可独立发布。

## 版本规划（已固定）

> 顺序即依赖链：补丁 → 架构地基 → 性能 → 单元同构 → 功能 → 观测 → 发布 → 平台线 → 稳定发布。每个版本 3~4 项同类工作，规模适合单次迭代闭环。
> 代号：0.8.x = Radix（扎根），0.9.x = Hedera（展藤），v1.0 = Mentha（常青薄荷）。

### v0.8.5「快速扫描与查询」（性能，已发布）

- NTFS 快速基线扫描（MFT/USN）+ 增量对账（USN 变更日志）+ 枚举兜底（`FindFirstFileEx` + `FIND_FIRST_EX_LARGE_FETCH` 或 `NtQueryDirectoryFile`）；拒权 / 非 NTFS / 网络盘自动降级 walkdir；硬链接去重、不跟随重解析点；依赖评估后引入 `ntfs-core` / `usn-journal-rs`。
- 索引与查询优化：keyset 分页替代 OFFSET、组合索引、COUNT 治理或延迟总数、标签过滤实测（逗号串 + LIKE vs 拆表 / 生成列）、FTS5 trigram 评估（CJK 单 / 双字保留 LIKE 回退）。
- 搜索语法增强：标签多值默认 OR 保持不变；新增显式 AND 语法（如 `label:a +label:b` 或 `label:a AND label:b`），后端解析、前端补全与帮助文案同步，边界矩阵补用例。
- 分类 / 规则匹配加速：Aho-Corasick 多模式匹配（课程名、忽略规则、文件名模式一次同时匹配）。
- 验收：5–10 万文件量级查询 / 扫描 / 滚动流畅；MFT 与 walkdir 结果一致；现有功能零回归；性能基准对比报告（自研 harness，15% 警示）。

### v0.8.6「规模与体积」（性能，两阶段执行，已发布）

> 0.8.6 合并 0.8.5 对接项，拆为两个阶段独立验收：阶段一「监控与查询性能」（风险最高放最前），阶段二「规模与体积」；全部完成后统一发布。
> 状态：阶段一已实施（2026-08-09）；阶段二与发布收口完成（2026-08-10，官方基线 0.8.6 vs 0.8.5-rerun 单轨对比）。扫描优化里程碑完成——MFT data runs / 子树定向 / skip_roots 对齐 / USN 句柄与日志 ID 修复 / attribute-list 大小兜底，真实目录 71,923 文件 MFT 与 walkdir 数量、大小、时间全等（size diff=0）；读取微优化带来 MFT 总耗时约 5%–8% 可测量下降；**原生 Win32 枚举器已落地为默认**（全链路等价 PASS，合成 50k 12.6x / 真实 4.3x，`ROOTUP_ENUM=walkdir` 可回退）；jwalk 复评未达门槛不引入；MFT 交叉点 50k 胜出，默认策略仍不启用（切换留后续里程碑）。

**阶段一「监控与查询性能」**

- 扫描优化（实验先行）：MFT 按 `$MFT` 映射对分 run 流式读取 + 原地 USA fixup + 紧凑索引 + 子树定向解析（小目录不再全卷重建路径）；与 walkdir 对齐 skip_roots；USN 卷句柄 `FILE_READ_DATA` + 真实 `UsnJournalID`；DB 批量 2000 + 多行 VALUES；分阶段计时入日志（read/parse/resolve/db）。
- MFT 快速基线 + USN 增量对账：首次以 MFT（提权验收后转默认）或 walkdir 建基线，日常读 USN 变更日志增量对账（upsert/delete 喂入现有差集链路）；权限 / 非 NTFS / 网络盘 / USN 日志裁剪自动回退并记录降级原因。
- FTS5 trigram 文本索引：附属表与 files 的同步 / 重建 / 一致性设计，评估后采纳；CJK 单字保留 LIKE 回退。
- 索引维护复核：安静环境复核 0.8.5 三个索引对 100k 扫描 / 重分类的写入代价，验证 `idx_files_type` 去留，必要时再收窄。
- 监控目录缺失对账：目录被删 / 盘符卸载 → 相关索引记录标记 deleted 或挂起并提示（修复幽灵文件与「目录不可访问后残留」），与 0.8.8 统一错误码体系预留对接。
- 扫描优化实验（0.8.6 内验证，默认不引入，决策门：等价全绿 + 收益显著才采纳）：
  - 并行 MFT 读/解析：按字节范围分线程读+解析再合并紧凑索引（FILE 记录相互独立，仅用 `std::thread`；参考 WizTree 多线程直读）。**已采纳为 MFT 默认读取策略**：read_ms 约 -27%（2.3–2.5s vs 3.3–3.4s），合成 50k / 边界 / 真实 71,923 三语料严格零差异；`ROOTUP_MFT_READ=sequential` 诊断回退、`ROOTUP_MFT_PARALLEL` 控制线程数，见 `benchmarks/mft-read-variants.md`。
  - 原生 Win32 枚举器：`FindFirstFileW/FindNextFileW` 直取 `WIN32_FIND_DATA`（大小 / 时间 / 属性），省掉 walkdir 每文件一次 `std::fs::metadata` 系统调用；作为新 `FileEnumerator` 与 walkdir 等价测试（参考 WinDirStat / Everything）。**已落地为默认枚举器**：等价全绿（Unicode / junction / 超长路径 / 单条目错误续枚举），全链路 DB 零差异，合成 50k 12.6x / 真实 Desktop 71,923 4.3x；`ROOTUP_ENUM=walkdir` 诊断回退，见 `benchmarks/enumerator-*.md` 与 `benchmarks/enum-compare.md`。
  - MFT 读取路径实验：直接读 `\\.\C:\$MFT`（`FILE_FLAG_BACKUP_SEMANTICS`）对比裸卷 DASD；`FILE_FLAG_NO_BUFFERING` + 对齐读。**结论：mftfile 本机打开被拒（自动回退，未采纳）；nobuffer 无收益（与 sequential 相当或更慢，未采纳）**，代码已移除，见 `benchmarks/mft-read-variants.md`。
  - jwalk 并行遍历复评（0.8.4 决策门到期）：deep/wide 语料 + feature 开关；行为等价且收益 ≥30% 才引入。**已复评：未达门槛（wide +13%、deep -16%，相对原生慢 8.8–11.9 倍），不引入**，原型已移除，见 `benchmarks/jwalk-evaluation.md`。
  - DB 写入微优化（两条路径共用）：`upsert_many` 子批 1000→2000/3000；`mark_scan_seen` 改多行 VALUES；用引擎基准验证收益。已验证：仅插入约 -10%，更新 / seen 无变化，未达 ≥30% 门槛，已回退，见 `benchmarks/enumerator-db-eval.md`。
  - 扫描选择优化器（已落地）：双线性模型——MFT 固定成本 = 最近一次 `read_ms`（随整卷文件表大小缩放），每文件成本 = 解析+落库实测；原生每文件成本 = 枚举+落库实测；交叉点 `N* = fixed/(native_per - mft_per)`，启用带 1.25× 迟滞；HDD/SSD 与目录结构差异大，不预设固定阈值，决策/校准日志见 `scan: 快速扫描决策`，模型在 `core/scan_choice.rs`。
- 验收：MFT/USN 与 walkdir 等价；降级矩阵全绿；写入代价回落或有明确去向；对账用例全绿。

**阶段二「规模与体积」**

- 前端体积（路线 A 落地）：React.lazy 页面级分割（首包仅文件页，加载占位高度不跳动）、语言包按需加载、Vite manualChunks 与构建产物压缩（gzip / brotli 评估）、首屏 JS ≤200KB。
- 性能基线与测量：0.8.6 全量重测并以 0.8.6 vs 0.8.5-rerun 为最新对比（同 OS 单轨）；帮助中心 0.8.6 更新亮点入库。
- 验收：体积 / 内存 / 启动指标达到基线；虚拟滚动与分包零布局回归；性能基准对比报告（自研 harness，15% 警示）。

### v0.8.7「单元同构」（架构，允许 schema v3 迁移，四阶段执行）

> 状态：阶段一已实施（2026-09-04）；插入项「前后端职责单一化治理」与「归档安全强化」已实施（2026-09-05/06）；**阶段二已实施（2026-09-06）**——units 统一索引（schema v8）、`kind:` 语法、项目单元入库、课程挂钩（别名 + course_overview）、文件页四视图；阶段三（软件单元识别）并入 v0.8.8 开头；阶段四（监看管道与快速扫描）拆散——「启动延迟注册」并入 v0.8.8 可靠性加固，其余独立为 v0.8.9「监看与快速扫描」。

**阶段一「契约与界面地基」**

> 状态：已实施（2026-09-04）。验收全绿：前端 467 项 / Rust 335 项测试、双端架构门禁（含事件名与 lucide 直连防漂移）、`check:version`；FilePage.test 断言零删除；真实应用深/浅 × 中/英 9 组前后矩阵截图对比无回归（`docs/reports/assets/0.8.7-phase1/`、报告见 `docs/reports/0.8.7-phase1-report.md`）。

## 已知技术挑战

- 避免直接归档正在下载的文件：通过检测文件读写占用判断下载是否完成。
- 应对「浏览器边下边写」的下载方式：设置缓冲文件夹，对特殊情况隔离等待。
- NTFS MFT/USN 快速扫描边界：仅本地 NTFS 卷可用，原始卷读取需管理员权限；USN 日志可能被裁剪或未启用，不能作为唯一数据源；MFT 硬链接与重解析点需去重 / 跳过；失败或拒绝提权时一律回退，保证行为等价。
- 智能解压安全边界：路径穿越、解压炸弹、超大文件、符号链接逃逸；先评估 zip 依赖再实现（v0.8.8）。
